# playroom-bot

мы создаём телеграмм бота, в котором можно будет бронировать игровую комнату в моём многоквартирном доме. комната находится в атриуме 4й секции жилого комплекса Амундсен, в ней есть кикер, две игровые приставки (PS5) и кинотеатр. минимальные слоты для брони - 1 час, максимальные - 5 часов нужно будет соблюсти безопасность - можно видеть только сам факт брони и свою бронь, видеть чужие брони нельзя требования будут накидываться по ходу

## Стек

- Go 1.26
- [go-telegram-bot-api/telegram-bot-api/v5](https://github.com/go-telegram-bot-api/telegram-bot-api) - клиент Telegram Bot API
- [modernc.org/sqlite](https://gitlab.com/cznic/sqlite) - чистый Go драйвер SQLite (без cgo)
- [joho/godotenv](https://github.com/joho/godotenv) - загрузка `.env` при локальной разработке

## Структура проекта

```
cmd/bot/            точка входа - сборка зависимостей и запуск
internal/domain/    доменные модели (Booking, Slot)
internal/booking/   бизнес-логика: Repository и Service интерфейсы
internal/storage/sqlite/  реализация Repository поверх SQLite
internal/telegram/  обёртка над Bot API, роутинг команд, обработчики
internal/config/    загрузка настроек из окружения/.env
```

Слои изолированы интерфейсами: `booking.Repository` не знает про SQLite,
`telegram.Bot` не знает про SQL - только про `booking.Service`. Это позволяет
менять хранилище или библиотеку Telegram, не трогая бизнес-логику.

## Требование безопасности

Чужие брони видно только как "занято/свободно" (`domain.Slot`, метод
`Availability`/`ListBusySlots`) - без владельца. Полные данные о брони
(`domain.Booking`) отдаются только через `MyBookings`/`ListByUser`, то есть
только самому владельцу.

## Запуск

```
cp .env.example .env   # и вписать токен от @BotFather
go run ./cmd/bot
```

## Команды

- `/start`, `/help` - краткое описание бота
- `/book ДД.ММ ЧЧ:ММ часы` - забронировать комнату, например `/book 10.08 14:00 2`
- `/my` - список своих активных броней
- `/cancel №брони` - отменить свою бронь (чужую - откажет)
- `/free` - занятость комнаты на ближайшую неделю вперёд

## Статус

Бизнес-логика и SQL-запросы реализованы, все команды работают end-to-end.

Отложено на потом: бронирование отдельных элементов комнаты (кикер/PS5/
кинотеатр по отдельности) - сейчас бронируется только комната целиком
(`domain.ResourceAll`). Колонка `resource` в БД и поле `domain.Booking.Resource`
уже заведены заранее со значением `all`, чтобы не делать миграцию данных
позже - сама возможность выбрать конкретный ресурс при бронировании ещё не
реализована (см. TODO в `domain`, `sqlite` и `telegram`).
